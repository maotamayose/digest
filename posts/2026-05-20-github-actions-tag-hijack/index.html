ライブラリやツールを使うとき、@v4 のようにバージョンを指定して固定します。タグは「この時点のこのコード」を指す動かない目印——そう思っていました。 でも、そのタグが指す中身は、本当に昨日と同じでしょうか。

【セキュリティ】"@v4" は固定ではなかった——人気Actionの全タグが書き換えられた

バージョンタグで固定したつもりの外部コードが、提供元の乗っ取りで丸ごと別物にすり替わりました。

■ 何が起きた？ GitHub Actions（テストやデプロイを自動実行する仕組み。他人が作った処理を「Action」として再利用できる）の人気Action actions-cool/issues-helper で、全タグが攻撃者の用意したコミットへ書き換えられました。 関連Action actions-cool/maintain-one-comment でも15個のタグが書き換えられています。 バージョンタグを参照しているワークフローは、次に実行された時に悪意あるコードを取り込みます。

■ 技術的な仕組み Gitのタグは可変です。リポジトリの書き込み権限を奪えば、既存のタグを別のコミットへ向け直せます。 今回、全タグが「通常のコミット履歴には現れないコミット」を指すよう移動されました。 実行されたコードはCIランナー上でメモリから認証情報を抜き取り、攻撃者のサーバーへ送信します。

■ なぜ防ぎにくいか @v1 @v4 というタグ参照は、最も普通の書き方です。 しかし「タグ＝不変」は誤った前提でした。 自分のワークフローファイルは1文字も変わっていないので、差分レビューでも気づけません。

■ これまでと何が違う？ ・攻撃者は新しい悪意あるパッケージを公開する必要がない。既存の人気Actionのタグを乗っ取るだけで成立する ・参照先がすり替わるだけなので、自分のリポジトリの履歴・差分には痕跡が残らない ・CI/CDが握るシークレット（デプロイキー・トークン）が直接の標的になる

■ これだけは覚えてほしい 外部のActionやCIテンプレートをバージョンタグで参照しているなら、コミットハッシュ（SHA）固定での参照に切り替え、迷う箇所は上長に相談していきましょう！

■ 自分はこう動く 自分も、依存先をバージョンタグで固定すれば安心だと思っていました。 参照先がいつの間にか別物になりうる前提で、自社リポジトリのCI設定に外部参照がないか棚卸しし、SO課と情報を共有しながら点検していきたいです。
