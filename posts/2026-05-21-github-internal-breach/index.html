【セキュリティ】GitHub の内部リポジトリ約4,000件が窃取されたと主張——入口は「汚染された VS Code 拡張」

エディタの拡張機能ひとつから、ソースコード管理基盤の内部リポジトリまで侵入が届いた事案です。

■ 何が起きた？

2026年5月20日、ハッカー集団「TeamPCP」が、GitHub 社の内部リポジトリ約4,000件を窃取したと主張しました。 GitHub 社は「攻撃者が言う約3,800件という数字は、現時点の調査と方向性として矛盾しない」と述べ、調査を進めています。 「4,000件」はあくまで攻撃者側の主張で、全件が完全に流出したと確定したわけではありません。 GitHub 社は「内部リポジトリの外にある顧客情報・顧客リポジトリへ影響した証拠はない」と説明しています。

■ 技術的な仕組み

侵入経路は、汚染された Visual Studio Code（VS Code）の拡張機能でした。 従業員の端末がその拡張経由でマルウェアに感染し、その端末を踏み台にして内部リポジトリへアクセスされたとされています。 TeamPCP は同時期に PyPI（Python のパッケージ配布元）の durabletask パッケージも汚染版に差し替えており、エディタ拡張・パッケージという「開発者が日常的に取り込むもの」を一貫して入口に使っています。

■ なぜ防ぎにくいか

拡張機能やパッケージは「自分で選んで入れたもの」です。 不審な添付ファイルや怪しいリンクと違い、こちらから取りに行って、使い続けます。 しかも一度入れた拡張は自動更新で中身が入れ替わります。入れた時点では正常でも、後から汚染版に差し替われば気づけません。 「怪しいものを開かない」という普段の警戒が、そもそも発動しない経路だということです。

■ これまでと何が違う？

  • 4月下旬〜5月上旬に共有した Vercel 事件（Chrome 拡張から約3億円相当が流出）と、入口は同じ「汚染された拡張機能」です。手口がブラウザからエディタへ広がっています
  • 狙われたのが個人の財布ではなく、ソースコード管理基盤の内部リポジトリそのものになりました
  • 従業員1台の端末の感染が、踏み台になって組織全体のコード資産に届きました。「端末1台くらい」では済まなくなっています

■ これだけは覚えてほしい

自分のエディタに今入っている拡張機能を一度見直し、使っていないもの・出所のあいまいなものは外すようにしましょう。 そして新しい拡張を入れるときは、提供元と評価を確認し、業務に必要か迷ったら上長に相談していきましょう。

■ 自分はこう動く

自分も VS Code の拡張を整理して、入れた理由を思い出せないものから外していきたいです。 GitLab（自社のソースコード管理）は、コードという最も守るべき資産が集まる場所です。 そこへの入口が、端末に入れた拡張ひとつになりうると分かった以上、SO 課の方々とも情報を共有しながら、自分の開発環境を継続的に点検していきたいです。
