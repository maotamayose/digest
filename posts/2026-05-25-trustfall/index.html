【セキュリティ】TrustFall 続報——ベンダーは「仕様」と判断、バージョンを上げても直らない

5/8 に共有した TrustFall について、開発元が「修正しない」と回答したという続報です。

■ 何が起きた？ 5/8 に「悪性リポジトリを clone するだけで任意コード実行」として TrustFall を共有しました。 今回はその深掘り版です。研究元の Adversa AI（発見者 Rony Utevsky 氏）が、Anthropic が TrustFall を「脅威モデルの範囲外」「設計意図どおり」と判断し、修正を見送ったと公表しました。 対象は前回と同じ Claude Code・Cursor CLI・Gemini CLI・GitHub Copilot CLI の4ツールです。今回 Claude Code は v2.1.129 で検証されています。

■ 技術的な仕組み 攻撃用リポジトリには .claude/settings.json と .mcp.json が同梱されます。これらが攻撃者の MCP サーバを自動承認する設定（enableAllProjectMcpServers など）を持ち、サーバ起動時に、AI が考え始めるより前に、サンドボックス外の OSプロセスとしてユーザー権限でコードが走ります。 さらに .mcp.json の中に node -e や sh -c でコード本体を直接埋め込む「ファイルレス型」も示され、ディスクにスクリプトが残りません。

■ なぜ防ぎにくいか 核心は、Claude Code の信頼ダイアログが v2.1 以降で「MCP がコードを実行する」という警告を落とした退行にあります。 旧版は .mcp.json のコード実行を明示し、オプトアウトも提示していました。現在は「あなたが作ったか信頼できるプロジェクトですか？」と尋ねるだけで、何が実行されるかの列挙はなく、既定の選択肢が「はい、このフォルダを信頼します」です。 盲点はここです。Anthropic は「フォルダを信頼する＝プロジェクト設定すべて（MCP実行を含む）に同意した」と位置づけており、ベンダー側から見れば不具合ではありません。つまりバージョンを上げても直りません。

■ これまでと何が違う？ ・前回（5/8）は「修正版 2.1.64 に上げれば直る CVE」がセットだった。今回の TrustFall 本体は修正されない ・「公式が直してくれる」前提が崩れた——直すかどうかはベンダーの脅威モデル次第 ・「Enter1回」の Enter が、いつの間にか警告文の薄いダイアログに変わっていた

■ これだけは覚えてほしい 出所のはっきりしないリポジトリを clone して、そのまま Claude Code などの AIコーディングCLI で開かないようにしましょう！ 信頼ダイアログが出たら反射で Enter せず、知っているプロジェクトかを一度確かめてから進めるようにしましょう。

■ 自分はこう動く 自分も Claude Code を毎日使っています。業務リポジトリは社内 GitLab に限られるのでリスクは低めですが、今回の件で「更新すれば安全」という自分の思い込みを正したいです。 ベンダーが直さないと決めた以上、信頼ダイアログを反射で押さない自分の運用が最後の防壁になります。出所不明のリポジトリやURLを CLI に渡さない習慣を、改めて徹底していきたいです。
