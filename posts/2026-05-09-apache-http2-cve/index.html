【セキュリティ】Apache HTTP Serverに「TCP1本・パケット2発」でクラッシュ＋RCE可能な穴——自社サーバの点検を

エンジニア向け色が強めの共有です。先日のAdobe PDFやAIコーディングCLIに続き、「アプリそのものに穴がある」型の脆弱性です。今回はWebサーバとして広く使われているApache HTTP Serverで、しかも認証不要・1接続2フレームで攻撃が成立します。

■ 何が起きた？ ・5月5日公表、CVE-2026-23918。Apache HTTP Server 2.4.66 の mod_http2（HTTP/2処理モジュール）にダブルフリー（同じメモリを2回解放する）の脆弱性。CVSS 8.8 ・攻撃者は HTTP/2 の HEADERS フレーム → RST_STREAM をTCP1接続上で素早く送るだけでワーカープロセスをクラッシュ可能（DoS） ・Debian系ディストロや公式 httpd Dockerイメージなど、よくあるデプロイ構成では遠隔コード実行（RCE）にエスカレートし得る ・修正版は 2.4.67

■ これまでと何が違う？ ・認証不要・パケット2発。スキャンbotが見つけ次第叩ける軽さ ・HTTP/2が有効なら影響対象。多くの本番Apacheが該当する可能性 ・「リバースプロキシ／ロードバランサ越しに守られているはず」が崩れる構成（公式Docker+Debian系）も明示的に挙げられている

■ これだけは覚えてほしい 自社で運用している Apache HTTP Server のバージョンと HTTP/2 有効化の有無を確認し、2.4.66 以下なら 2.4.67 へ更新するようにしましょう！判断に迷う場合は上長に相談してください！

（補足・確認方法） ・バージョン確認: httpd -v または apache2 -v ・HTTP/2有効化: httpd.conf または apache2.conf で Protocols h2 h2c http/1.1 の有無 ・Dockerなら httpd:2.4.66 系イメージを使っていないか

■ 自分はこう動く 自分が触っているプロダクトのインフラ構成を確認し、Apacheが残っていれば優先的にバージョンと設定を点検します。SO課の方々と相談しながら、本件のような「認証不要RCE」の穴は、自分たちが直接運用していないサーバについても情報共有していきたいです。
